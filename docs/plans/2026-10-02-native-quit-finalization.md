# Ordinary macOS termination and session finalization

The application menu, Cmd-Q, tray and Settings already use `commands::quit_application`: stop capture/providers, finish private session files, and exit only after a successful save. AppKit's ordinary Dock Quit instead reaches Tao 0.35.3's `applicationWillTerminate`, which exits directly. Intercept `applicationShouldTerminate` with a public, main-thread-only NSApplicationDelegate wrapper. Return `TerminateCancel`, then asynchronously run the existing normal quit command. Do not use `TerminateLater` or activate/focus the app on successful exit.

NSApplication's delegate reference is weak. A thread-local registration strongly retains the wrapper and original Tao delegate. `respondsToSelector` advertises both wrapper/superclass and original callbacks; `forwardingTargetForSelector` forwards optional callbacks to the original receiver. This preserves Tao's launch, reopen, URL and user-activity callbacks and its original private ivar layout. On Exit, restore the original only while NSApplication still points to this wrapper; never replace a later owner's delegate.

Tao's startup state accesses use its separately owned original delegate. However, its runtime `set_dock_visibility` API downcasts NSApplication's current delegate to NSObject and reads Tao's private `auxState` ivar. That API is incompatible with a forwarding wrapper: Mimi must keep using the existing direct AppKit activation-policy implementation. Current Rust/frontend/plugin code has no such call and no capability grants the built-in command. A source/capability contract test protects this boundary; a future caller needs a separate safe integration rather than forwarding that raw ivar access.

One shared RAII quit gate prevents duplicate stop/save operations across simultaneous native, menu, tray and IPC requests. Cancellation and save failure release it for retry; a successfully queued exit keeps it closed. On native save failure, keep the app and pending archive alive and open the existing Export page, which exposes the content-free save error and retry/export actions. No credentials, caption content, paths or provider errors are added to diagnostics.

Focused tests cover actual Objective-C forwarding to an original object with a different ivar layout, optional/unknown selectors, owner-only restoration, duplicate requests, save-failure retry and cancelled-future retry. Signed native acceptance must separately check Dock Quit, Cmd-Q, repeated menu/Dock requests, save failure, Dock reopen and existing responder actions. This change does not claim to make Force Quit, OS logout or shutdown finalize sessions safely.
